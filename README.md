# Alembic baseline fix

The baseline generated by:

    alembic revision --autogenerate -m "Initial Trade Opportunity schema"

incorrectly detected Alembic's own version table as a removed table. It then
generated a DROP TABLE for alembic_version. That caused Alembic to drop its
version table and immediately fail when it tried to record the new revision.

## Apply the fix

1. Copy the supplied env.py into:

    app/db/migrations/env.py

2. Run:

    ./patch_baseline_migration.sh

3. Do NOT create another migration.

4. Run:

    alembic current
    alembic heads
    alembic upgrade head

The existing failed upgrade used transactional DDL, so it should have rolled
back its schema/table work. A full Docker reset is not required just for this
fix.

The application Alembic version table is intentionally kept in:

    trade_opportunity.alembic_version

and explicitly excluded from autogenerate.
